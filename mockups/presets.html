Presets d'exercices : 3 propositions

Même app, même grille (sidebar + contenu). Seul l'emplacement du système de presets change. Les zones en pointillés bleus sont les ajouts. Les listes et menus sont montrés ouverts pour la lisibilité.

Principe

Un sélecteur à droite du titre, toujours visible : il affiche l'exercice chargé, ouvre la liste, et un bouton « Enregistrer » à côté.

Pour

  • Aucune place prise dans la grille : l'en-tête a de l'espace à droite
  • Accessible même quand la sidebar est scrollée
  • Le nom de l'exercice chargé et l'état « modifié » restent sous les yeux

Contre

  • Liste dans un menu : moins confortable au-delà de ~30 presets (d'où la recherche)
  • Sur mobile, le menu passe sous le titre

Principe

Un nouveau panneau repliable en tête de sidebar, au même format que les autres : champ nom + bouton, puis la liste.

Pour

  • Cohérent avec l'UI existante (mêmes panneaux)
  • Liste toujours visible quand le panneau est ouvert, confortable pour beaucoup de presets
  • Replié, le résumé montre l'exercice chargé

Contre

  • Rallonge une sidebar déjà longue : il faut replier pour retrouver les réglages
  • Invisible quand on a scrollé la sidebar

Principe

Un bouton « Mes exercices » à droite de l'en-tête (ou la touche E) ouvre un tiroir par-dessus le contenu : enregistrement en haut, cartes détaillées en dessous. Fermeture : croix, clic sur le fond, Échap, ou clic sur un exercice (qui le charge).

Pour

  • Zéro impact sur la grille, beaucoup de place pour une vraie bibliothèque (cartes, mini-manche, tags, tri)
  • Idéal si les presets deviennent nombreux ou si on ajoute des exercices fournis

Contre

  • Masque l'app pendant qu'il est ouvert : pas de comparaison immédiate
  • Un clic de plus pour charger un exercice
  • Plus de code (focus trap, Échap, animation)

Commun aux 3 propositions (moteur identique)

  • Un preset = { id, nom, query, créé, modifié } où query est la query string de l'URL : on réutilise le codec existant, donc un preset ancien reste lisible (valeurs invalides ignorées, défauts complétés).
  • Stockage localStorage sous une clé versionnée, lectures et écritures protégées (navigation privée, stockage plein ou bloqué) : l'app marche sans.
  • Exercice chargé suivi : badge « modifié » dès qu'un réglage change, bouton « Mettre à jour » ou « Enregistrer sous ».
  • Nom pré-rempli depuis les réglages (« C dorien · Box · Best path »), renommer, dupliquer, supprimer avec annulation.
  • Export / import JSON pour sauvegarder ou passer d'un navigateur à l'autre.
  • Synchronisation entre onglets (événement storage).
